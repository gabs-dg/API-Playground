ℹ️ Sobre o Projeto

O API Playground é uma aplicação web desenvolvida para facilitar a exploração e o consumo de APIs públicas através de uma interface gráfica.

A proposta é permitir que você selecione uma API, configure uma requisição, envie a solicitação e visualize a resposta retornada pelo servidor sem precisar escrever código ou utilizar ferramentas externas complexas.

Nota Importante

O API Playground não tem como objetivo substituir ferramentas profissionais como Postman ou Insomnia. A proposta é oferecer uma experiência mais simples e didática para aprender e testar requisições HTTP.

⚙️ Como Funciona

O fluxo da aplicação é dividido em cinco etapas principais:

  1. Seleção da API: Escolha uma das APIs do catálogo ou insira seu próprio endpoint.
  2. Configuração: Defina o método HTTP, URL, parâmetros, headers e body conforme necessário.
  3. Execução: Ao clicar em "Send", o JavaScript utiliza a Fetch API para fazer a requisição.
  4. Processamento: A resposta é analisada, extraindo Status HTTP, tempo de resposta, Content-Type e os dados brutos.
  5. Visualização: A interface apresenta o JSON formatado de forma clara e legível.

🏗️ Arquitetura

O projeto foi organizado separando a comunicação com APIs da camada responsável pela apresentação dos dados, seguindo o princípio da Separação de Responsabilidades:

API Layer

Responsável pela comunicação HTTP, endpoints, parâmetros, headers, parsing das respostas e tratamento de erros.

UI Layer

Responsável pelo HTML, componentes visuais, eventos do DOM, apresentação dos dados e responsividade.

💡 Decisões Técnicas

Por que JavaScript/TypeScript puro?

A ausência de frameworks como React ou Vue é intencional. O objetivo é compreender e demonstrar o funcionamento fundamental de uma aplicação Web antes de adicionar abstrações. Conceitos como fetch(), async/await, Promise, DOM e Modules são utilizados diretamente.

Separação de Responsabilidades

A interface não executa chamadas de API diretamente nos eventos. Preferimos usar uma camada de serviço:

typescript 
// Evitar: Lógica misturada no evento
button.addEventListener("click", async () => {
    const response = await fetch("https://api.example.com/users");
    // ... toda a lógica aqui
});

// Preferir: Separação clara
button.addEventListener("click", async () => {
    const result = await getUsers(); // Camada de serviço
    renderUsers(result);             // Camada de UI
});

🚀 Primeiros Passos

Fazer sua primeira requisição leva menos de 10 segundos:

  1. Abra o Request Builder no menu superior.
  2. Selecione o método HTTP (GET, POST, PUT, etc).
  3. Cole a URL do endpoint no campo de texto.
  4. Clique em SEND REQUEST ou pressione Ctrl + Enter.
Dica Pro

Use o catálogo lateral para buscar APIs públicas (como GitHub, Discord, OpenWeather) e carregar endpoints prontos com um clique.

📦 Exportação de Código

Ao clicar no botão Exportar, você pode gerar o código da sua requisição atual em várias linguagens. Exemplo de saída cURL:

bash 
curl -X POST "https://api.exemplo.com/v1/users" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -d '{"name": "Ada", "email": "ada@example.com"}'

🔐 Autenticação

O API Playground suporta os métodos de autenticação mais usados no mercado:

  • Bearer Token: Insira seu token JWT ou OAuth2. Ele será enviado automaticamente no header Authorization.
  • Basic Auth: Forneça usuário e senha. As credenciais são codificadas em Base64 antes do envio.
  • API Key: Configure o nome do header (ex: X-API-Key) e o valor da sua chave.

🛠️ Troubleshooting

Erro de CORS (Cross-Origin Resource Sharing)

Se você receber um erro de CORS, o servidor da API não permite requisições diretas do navegador. O API Playground roda 100% no cliente, sujeito às restrições de segurança do browser.

Solução

Use APIs que permitem CORS (como JSONPlaceholder). Para APIs privadas, use uma extensão de navegador que desabilite CORS temporariamente apenas para desenvolvimento.

A resposta está vazia ou com erro 404

Verifique se a URL está completa (incluindo https://) e se o método HTTP selecionado é o correto para aquele endpoint.
